### 決定 5：ダイアログで `ERR-CONFLICT` になったときの表示

- 仕様の ID：共通仕様 7 節 `ERR-CONFLICT`、`EV-ORD-402` 手順 3・6、`EV-ORD-403` 手順 3・6、`DEC-ORD-34`

  3. ダイアログを閉じ、元画面を再読み込みしてエラーを出す：ダイアログが消え、何が起きたか見えにくくなります。

### 決定 6：在庫不足（`ERR-BIZ`）のときのダイアログ

- 仕様の ID：共通仕様 7 節 `ERR-BIZ`、`EV-ORD-402` 手順 4-2、`EV-ORD-403` 手順 4
- 背景：7 節は `ERR-VALIDATION` を「入力値を保持したまま画面に留まる」と明記しますが、`ERR-BIZ` は「違反内容に応じたメッセージを表示し、処理を行わない」とだけ書きます。
- 問い：在庫不足のとき、ダイアログは閉じるか留まるか。留まるなら入力をどうするか。
- 選択肢と結果：
  1. 留まり、入力値を保持し、エラーをダイアログに出す（同じ `RowVersion` でやり直せる。内訳の在庫を最新にするかは定めない）：在庫の補充を待って、同じ入力でやり直せます。
  2. 留まり、DB の最新で再表示する（入力は捨てる）：受注は更新されていないのに入力を失います。
  3. ダイアログを閉じ、元画面にエラーを出す：入れた出荷日・送料を失い、開き直しになります。
  4. 定めない：在庫不足の後の画面を確かめません。
- 推奨と理由：1。`ERR-VALIDATION` と同じく「業務の違反は画面に留まる」型で、受注は変わっていないので入力を捨てる理由がありません。
- 影響するケース：E2E `確定_在庫不足はダイアログに留まりエラーを出す`
- 記録先：仕様の決定記録（`LLD/Decisions/Orders.md`）
- 判断：GO（1。ダイアログに留まり、入力値を保持してエラーを出す）。2026-11-25 に代行が選んだ（決めた者：代行（842ff281-c6cc-4685-bce6-36c31293e8fe・claude-opus-5-5）。依頼 011）。記録済み（NorthwindDbSampleSpec@2962688 の `DEC-ORD-54`。代行が 2026-11-25 にコミット。依頼 012）
