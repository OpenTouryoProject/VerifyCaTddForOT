### 壊す確かめの方針（段 2 の報告に書くこと）

- (a) **net10.0 で流す 57 テストケースのどれもが、いずれかの壊し方で落ちる**ように、B層の実装（`OrdTfBusiness`・SQL 定義）の壊し方の一覧を組む。壊し方は 1 か所ずつ一時的に壊して戻す（戻したファイルの更新時刻を今にしてから流す）。**ケースと壊し方の対応を表にして、段 2 の報告に書く**（どの壊し方でも落ちないケースが残ったら、そのケースは実装を見ていない＝テストの誤りとして報告する）。
- (b) **壊し方ごとに、落ち方の例（`But was:` などの実際の値）を記録し、意図した壊し方の値になっていること**を確かめる（壊し方が効かず別の形で壊れても「落ちた」になるため）。戻した後の全件の結果も書く。

### 8.7 段 2 の確かめ方（予定）

- **Red**
  - B層：`OrdTfParameterValue` に `SortColumn`・`SortDescending` のメンバだけを足す（テストをコンパイルするための足場。以前の B層の「空の UOC」と同じ扱い）。`OrdTfBusiness`・SQL 定義は変えない。新しい 25 テストケースのうち、並びが既定と異なるものが `Assert` で落ちる。既定の並びと同じ結果になるケース（8.2 の「最初から通るケース」：受注日の降順・受注 ID の降順・並べ替えの列が空・同じ値が続いても…の件数と重複の部分）は通る。**どれが通ったかを段 2 の報告に書く**。
  - 画面：並べ替えの見出しの操作（`#sort…`）が無いので、E2E の新しい 17 テストケースは `Expect`（見出しの操作が在ること）で落ちる。アプリの起動・ログインで落ちるのは Red ではない。段 2 では画面に要素を足さない。
- **B層（net48・net10.0 の両方）**：新しいケースを足した状態で、**どちらのランタイムでも**既存を含む 82 テストケースを流す。順に流す（同時に流さない。本書 1 章の「並行実行」）。net48 は MSBuild で `MVC_Sample\MVC_Sample.Tests` を組んで `dotnet test <csproj> --no-build`、net10.0 は `dotnet test MVC_Sample_Core\MVC_Sample.Tests`（`opentouryo-test-layer-b`）。
- **壊す確かめ（段 4 の Green の後、段 2 の方針に従って B層の実装を 1 か所ずつ一時的に壊して戻す）**：3 章の方針（ケースと壊し方の対応表・落ち方の例・戻した後の全件）に、次の壊し方を足す。
  - (a) 並べ替えの指定を無視して既定の並びのまま返す（8.2 の昇順の 7 つ・降順の多く・並びの 4 件が落ちる）。
  - (b) 方向を取り違える（`SortDescending` の昇順と降順を逆にする。14 テストケースの昇順と降順の両方）。
  - (c) 列の対応を 1 列ずつ別の列に取り違える（7 通り。列ごとのケースがそれぞれ落ちる）。
  - (d) `OFFSET` の計算を誤らせる（ページごとの 20 件・同じ値が続いても重ならず抜けないが落ちると見込む）。**最後の並べ替えキー（受注 ID）を外す壊し方は、同じ値の 45 行を同じ実行計画が同じ順で返せば落ちない可能性がある**ので、見込みで書かず、段 2・段 4 で実際に流して落ちるかを記録する。落ちなければ、受注 ID を外す壊し方では「同じ値が続いても…」を検出できないことを報告に書き、このケースを落とす別の壊し方（OFFSET の計算の誤りなど）を対応表に書く。
  - (e) 抽出条件を並べ替えの指定のときだけ外す（並べ替えは抽出条件と併用するが落ちる）。
