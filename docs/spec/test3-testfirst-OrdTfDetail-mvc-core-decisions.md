### 決定 1：顧客住所の区切り

- 仕様の ID：`SC-ORD-02-I05`
- 背景：画面定義書は顧客住所を「`Customers.Address` + `City` + `Region` + `PostalCode` + `Country`」「空の要素を詰めて連結する」とするだけで、区切りの文字を書いていない。同じ画面の担当者名（`SC-ORD-02-I06`）は `LastName + " " + FirstName`（`EMP-T1`）と区切りを明記している。
- 問い：住所の要素を、どの文字で区切って連結するか。
- 選択肢と結果：
  1. 半角空白：例「Obere Str. 57 Berlin 12209 Germany」。テストは連結した文字列を完全な一致で確かめる。
  2. 全角空白：英字の住所に全角空白が入る。テストは同上。
  3. 区切りなし：「Obere Str. 57Berlin12209Germany」と読みにくい。テストは同上。
  4. 読点（`、`）または `, `：「Obere Str. 57, Berlin, 12209, Germany」。どちらかをさらに選ぶ必要がある。テストは同上。
  5. 定めない（実装に任せ、テストの期待にしない）：テストは各要素が順に含まれることだけを確かめる。利用者に見える形は実装次第。
- 推奨と理由：1。担当者名の連結（半角空白）と揃い、住所の並びが西洋式（番地・市・地域・郵便番号・国）で空白区切りが自然。4 は読みやすいが記号の選び方がさらに要る。5 は表示の形が決まらない。
- 影響するケース：B層 `OrdTfDetail_顧客住所は…`、E2E `詳細_顧客住所は…`
- 記録先：仕様の決定記録（`LLD/Decisions/Orders.md`）
- 判断：GO（5。定めない）。2026-11-24 に代行が選んだ（決めた者：代行（842ff281-c6cc-4685-bce6-36c31293e8fe・claude-opus-5-5）。依頼 001）。推奨と違う。要レビュー。記録済み（NorthwindDbSampleSpec@ec66d6e の `DEC-ORD-18`。代行が 2026-11-24 にコミット。依頼 002）

### 決定 4：遷移だけのボタンをメインボタンに含めるか（規約の解釈）
