## 決定 1

- 仕様の ID：`EV-ORD-102`・`EV-ORD-104`（検証エラーの直後の一覧）、`DEC-ORD-03`
- 背景：`DEC-ORD-03` は、検証エラー（`ERR-VALIDATION`）のときは「一覧・総件数・ページ情報と一覧状態の保持は更新せず、直前の表示のまま残す」と決めている。
  今の実装（ケース1・ケース2 とも同じ作り）は、検証エラーのとき、保持している条件とページで B層をもう一度呼び、その結果を一覧として出す。
  直前に表示してから、エラーになる操作までの間に、他の利用者が受注を追加・削除すると、再取得した結果は「直前に実際に表示していた行・件数」と変わりうる
  （削除されて 0 件になれば、「該当するデータがありません。」も出る）。テストは、この場面を扱っていない。
- 問い：他の利用者がデータを変えていたときの「直前の表示のまま」は、どちらか。
- 選択肢：
  1. 定めない（実装に任せ、テストの期待にしない）。結果：今の実装（取り直し）のまま。テストは増えず、ほかのケースにも同じ扱いになる。仕様の読みは決まらず、後で別のケースで同じ問いが再び出る可能性がある。
  2. 同じ条件で取り直した結果を出す（今の実装のまま）。結果：画面は常に最新の内容で、実装は変わらない。「更新しない」の読みが、保持の状態（条件・ページ）に限られる。E2E で確かめにくい（他の利用者の操作を作る必要がある）ので、B層のテストか手動の確認になる。
  3. その時点で実際に表示していた行・件数をそのまま残す。結果：実装は、直前の表示を持ち回る（hidden にサーバが全行を持つか、再取得しない）作りに変わり、手間が増える。画面は古い内容のまま残りうる。
- 推奨と理由：1（定めない）。サンプルの利用者が通常する操作ではなく、他の決定に影響しない。決めるなら 2（今の実装で済む）。
- 影響するケース：なし（2・3 が選ばれたら、テストを足すか実装を変える）。ケース1・ケース3 にも同じ問いが出る。
- 記録先：仕様の決定記録（`LLD/Decisions/Orders.md`）
- 判断：GO（1。定めない）。2026-11-14 に人が選んだ。記録の案：NorthwindDbSampleSpec の `LLD/Decisions/Orders.md` に DEC-ORD-11 として書いた（ワーキング ツリー。コミットは人。索引の件数も 11 に更新）
