# テスト先行：レビューの観点（受注帳票プレビュー OrdTfReport）

**レビュー役が使う**（司令役が渡す）。段 1（テスト仕様）・段 2（Red）・段 4（Green）を承認する前に、ここと突き合わせる。
**実装役には読ませない**（読むと、仕様からテストを起こす力を確かめられない）。

どの対象にも共通の観点は [cmn-testfirst-review.md](./cmn-testfirst-review.md)（両方を使う）。
仕様の出どころは [spec/test3-testfirst-OrdTfReport.md](../spec/test3-testfirst-OrdTfReport.md)。段 1 のテスト仕様に、次が入っているか。

| 種類 | 観点 | 根拠 | 入っているべきケース（例） |
| --- | --- | --- | --- |
| B層 | 読み込み | `EV-ORD-501` 手順 1〜3 | 無い受注 → NOTFOUND。担当者名・配送業者名は外部結合（担当者・配送業者が無い受注も表示できる）。明細は商品名の昇順 |
| B層 | 金額 | `EV-ORD-501` 手順 4、「金額の再計算」、`HLD/Common.md` 3 節、`OD-T4` | 10 進数で計算（`Discount` は real）。明細金額の小数第 3 位の四捨五入。小計・合計。送料が NULL の扱い（`DEC-CMN-03`） |
| B層 | 宛先 | `EV-ORD-501` 手順 6、`SC-ORD-05-I05` | 出荷先の 6 項目を使い、顧客マスタの住所を使わない（顧客と出荷先が違う受注で確かめる）。空の要素の扱いを推測で決めていない |
| B層 | 書き換えない | `EV-ORD-501` 手順 8、`EV-ORD-502` 手順 3 | 読み込みの前後で、受注・明細の値と `RowVersion` が変わらない |
| E2E | 遷移 | `EV-ORD-204`、`SC-ORD-02-B04`・`B05` | 詳細の「納品書」で納品書、「請求書」で請求書が初期選択。無い受注 ID → ERR-NOTFOUND の扱い（7 節） |
| E2E | 種別ごとの表示 | `EV-ORD-501` 手順 5・7、`SC-ORD-05-I07`・`I08`・`I14` | 納品書：タイトル「納品書」、出荷日・配送業者が出て、支払期限が出ない（出荷日が NULL なら空）。請求書：タイトル「請求書」、支払期限＝発行日の翌月末日、出荷日・配送業者が出ない |
| 共通 | 支払期限の境界 | `SC-ORD-05-I14` | 翌月末日の算出（月の日数の違い・年をまたぐ 12 月・うるう年の 2 月）。当日に依存するので、B層か P層の計算を、日付を与えて確かめる作りか |
| E2E | 種別の切替 | `EV-ORD-502` | 切り替えでタイトルと表示の項目が変わる。DB を読み直さない（確かめ方は計画で決めてよいが、テスト仕様に書いてある） |
| E2E | 印刷 | `EV-ORD-503` | 印刷の媒体で、帳票種別・印刷・戻る・ヘッダ・メニューが表示されない。帳票の本文は表示される。印刷を押すとブラウザの印刷機能が呼ばれる（印刷のダイアログを開かずに確かめる） |
| E2E | 戻る | `EV-ORD-504` | 同じ受注の詳細へ戻る |
| E2E | メインボタン | 範囲の「前の回から引き継ぐこと」 | 印刷をメインボタンに含めるかを、規約の解釈として仕様の決定に上げているか（推測で置いていないか）。詳細の `B04`・`B05` と戻るはフッタの外 |
| 共通 | 受注詳細の決定の広がり | 範囲の「前の回から引き継ぐこと」 | `DEC-ORD-18`・`24` など受注詳細の決定を、この画面へ黙って広げていないか（広げるなら仕様の決定に上げ、根拠に書く） |
| 共通 | テストのデータ | 範囲の「データを書き換えるテスト」 | 既存の行を書き換えない。テストが作った行は後片付けで消す |
| 共通 | 前の回の約束 | 範囲の「前の回から引き継ぐこと」 | 前の回までの E2E（一覧・詳細・登録・編集・出荷）の期待を変えない（変えるなら期待値の変更） |
