# テスト先行：レビューの観点（受注管理の直し OrdTfRevise）

**レビュー役が使う**（司令役が渡す）。段 1（テスト仕様）・段 2（Red）・段 4（Green）を承認する前に、ここと突き合わせる。
**実装役には読ませない**（読むと、仕様からテストを起こす力を確かめられない）。

どの対象にも共通の観点は [cmn-testfirst-review.md](./cmn-testfirst-review.md)（両方を使う）。
仕様の出どころは [spec/test3-testfirst-OrdTfRevise.md](../spec/test3-testfirst-OrdTfRevise.md)。段 1 のテスト仕様に、次が入っているか。

| 種類 | 観点 | 根拠 | 入っているべきケース（例） |
| --- | --- | --- | --- |
| 共通 | 期待値の変更の洗い出し | 範囲の「期待値の変更」 | 前の回までのケースのうち期待が変わるものを、テスト仕様に漏れなく挙げている（`[Basis("DEC-ORD-24")]`・`66` のケース、日付の入れ方、削除、ページング）。変えないケースを黙って変えていない |
| B層 | マスタに無い明細の金額 | `DEC-ORD-24`・`66`、`DEC-CMN-02` | 詳細・帳票の小計・合計に含め、**受注一覧の合計金額と一致する**（同じ受注で一覧と詳細の金額を比べる）。明細金額の丸め（共通仕様 3 節）も同じ |
| 共通 | マスタに無い明細の表示 | `DEC-ORD-73`・`74`・`75` | 詳細・編集：「（商品マスタに無い：ID n）」・在庫が空・「（廃番）」が付かない・警告が 1 つ。帳票：商品 ID だけで注記も警告も無い。並び：商品名のある行の後に商品 ID の昇順（名前のある行が複数・マスタに無い行が複数で確かめる） |
| B層 | 編集の保存 | `DEC-ORD-76`、`DEC-ORD-49` | マスタに無い既存の行を残したまま保存できる・数量などを変えられる・行を削除できる。**既存の行かは DB で決める**：DB に無いのに読み込み時の行を名乗る、マスタに無い商品 ID の行は `VAL-EXISTS` で止まる |
| B層 | 出荷 | `DEC-ORD-77` | マスタに無い明細があっても確定・取消でき、ほかの明細の在庫だけが動く。内訳に出る（在庫が空・強調しない） |
| 共通 | 出荷済の削除 | `DEC-ORD-78`、`DEC-ORD-60` の原則 | E2E：出荷済で削除が非活性。B層：DB が出荷済なら `ERR-BIZ`「出荷済の受注は削除できません。」で、受注・明細が残る（画面の活性に頼らない）。未出荷は従来どおり削除できる |
| 共通 | 状況の判定 | `DEC-ORD-27` | 同じ日で時刻が後の出荷は遅延にしない、翌日の出荷は遅延。**表示と抽出条件「納期遅延」の両方**で確かめる（時刻付きのデータはテストが入れる） |
| E2E | 在庫超過の警告 | `DEC-ORD-44` | 2 行が超えた状態で 1 行を直しても警告が残り、両方直すと消える。行の削除で超える行が無くなると消える。読み込みで既存の行が超えていれば出る |
| E2E | ページ番号の入力 | `DEC-CMN-08` | 番号＋Enter で移る（条件・並び順を保つ）。総ページ数より大きい→最終ページ、0 以下→1 ページ目。空・文字・小数→移らず入力欄が今の番号に戻り、メッセージが出ない。ボタンとページ情報は今のまま |
| E2E | 日付の入力 | 規約「画面共通」 | `type="date"` であること。値を入れて検索・保存・出荷できる。入力途中で送ると形式の違反が項目の直下に出て、送られない（検索の条件が黙って消えない） |
| 共通 | B層が受ける日付の形 | 範囲の「期待値の変更」 | `yyyy-MM-dd` を受ける作りにしたなら、B層のテストもその形で入れている（実装の決定を計画に書いている） |
| 共通 | ケース1・3 | 範囲の「ケース1・3 への波及」 | 終わりにケース1・3 の画面の E2E を流す手順が計画にある。B層のテストは net48 でも流す |
| 共通 | テストのデータ | 範囲の「データを書き換えるテスト」 | 既存の行を書き換えない。マスタに無い明細はテストが作った受注に入れ、後片付けで消す |
| 共通 | 実装の記録を根拠にしていない | 範囲の「直す範囲」 | `LLD/ImplementationNotes` の記述を期待にしていない（根拠は本文と決定記録だけ） |
