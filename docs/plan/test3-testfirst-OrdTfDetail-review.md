# テスト先行：レビューの観点（受注詳細 OrdTfDetail）

**レビュー役が使う**（司令役が渡す）。段 1（テスト仕様）・段 2（Red）・段 4（Green）を承認する前に、ここと突き合わせる。
**実装役には読ませない**（読むと、仕様からテストを起こす力を確かめられない）。

どの対象にも共通の観点は [cmn-testfirst-review.md](./cmn-testfirst-review.md)（両方を使う）。
仕様の出どころは [spec/test3-testfirst-OrdTfDetail.md](../spec/test3-testfirst-OrdTfDetail.md)。段 1 のテスト仕様に、次が入っているか。

| 種類 | 観点 | 根拠 | 入っているべきケース（例） |
| --- | --- | --- | --- |
| B層 | 1 件の取得と結合の NULL | `EV-ORD-201` 手順 1・2 | 顧客・担当者・配送業者が NULL の受注も取れ、空になる（外部結合） |
| B層 | 無い受注 | `EV-ORD-201` 手順 1、`ERR-NOTFOUND` | 存在しない受注 ID で NOTFOUND（例外でなく、P層が区別できる形） |
| B層 | 明細の並びと結合 | `EV-ORD-201` 手順 3 | 商品名の昇順。`Products` は内部結合 |
| B層 | 金額 | `EV-ORD-201` 手順 4、「金額の再計算」、`HLD/Common.md` 金額の算出式、`DEC-CMN-02`・`03` | 価格・明細金額（小数第 3 位の四捨五入。`Discount` は real なので 10 進数で計算）・小計・合計。明細 0 件・送料 NULL |
| B層 | 状況・廃番 | `EV-ORD-201` 手順 5・6、`ORD-T7` | 未出荷・出荷済・納期遅延（`RequiredDate` NULL は遅延にしない）。廃番の商品名に「（廃番）」 |
| B層 | 行バージョン | `EV-ORD-201` 手順 7 | 取得の結果に `RowVersion` がある |
| B層 | 削除の順と同じトランザクション | `EV-ORD-203` 手順 2〜5、`ORD-T8` | 明細と受注が両方消える。受注を消せないときは明細も残る（ロールバック） |
| B層 | 競合と無いの区別 | `EV-ORD-203` 手順 4、`HLD/Common.md` 9.1 節 | 行バージョンが違う → CONFLICT、受注が無い → NOTFOUND（**区別する**） |
| E2E | 一覧から詳細へ | `EV-ORD-106` | 受注 ID の選択で、その受注の詳細が出る |
| E2E | 一覧状態の復元 | `EV-ORD-106` 手順 1、`EV-ORD-206`、F-2 | 絞り込み・ページ・並べ替えをしてから詳細へ行き、「一覧へ戻る」で同じ条件・ページ・並びに戻る |
| E2E | 新規登録への遷移 | `EV-ORD-107`、範囲の「まだ無い画面への遷移」 | 「新規登録」で登録モードの `SC-ORD-03` の URL へ行く（受注 ID を渡さない） |
| E2E | 表示 | `SC-ORD-02-I01`〜`I20`、`I17` の列 | 割引率は百分率、出荷日 NULL は空、住所は空の要素を詰めて連結、合計 |
| E2E | 編集の活性 | `EV-ORD-201` 手順 8、`ORD-T4` | 出荷済で非活性、未出荷で活性 |
| E2E | 無い受注 | F-4、`ERR-NOTFOUND` | 「対象のデータは存在しません。」を出して受注一覧へ |
| E2E | 削除の確認 | `EV-ORD-203` 手順 1、`HLD/Common.md` 削除の確認 | 確認の文言。取り消すと何も消えない |
| E2E | 削除の後 | `EV-ORD-203` 手順 6 | 「受注 ID nnn を削除しました。」、保持した一覧状態で一覧へ、一覧は再検索（総件数が減る） |
| E2E | 削除の競合 | `EV-ORD-203` 手順 4、`ERR-CONFLICT` | 表示の後に他で更新された受注を消そうとすると、競合のメッセージで消えない |
| 共通 | テストのデータ | 範囲の「データを書き換えるテスト」 | 削除はテストが作った受注だけ。落ちても後片付けで消える |
