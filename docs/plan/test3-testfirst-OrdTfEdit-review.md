# テスト先行：レビューの観点（受注詳細 登録・編集 OrdTfEdit）

**レビュー役が使う**（司令役が渡す）。段 1（テスト仕様）・段 2（Red）・段 4（Green）を承認する前に、ここと突き合わせる。
**実装役には読ませない**（読むと、仕様からテストを起こす力を確かめられない）。

どの対象にも共通の観点は [cmn-testfirst-review.md](./cmn-testfirst-review.md)（両方を使う）。
仕様の出どころは [spec/test3-testfirst-OrdTfEdit.md](../spec/test3-testfirst-OrdTfEdit.md)。段 1 のテスト仕様に、次が入っているか。

| 種類 | 観点 | 根拠 | 入っているべきケース（例） |
| --- | --- | --- | --- |
| B層 | 読み込み（編集） | `EV-ORD-301` 手順 3、`ORD-T4`、`ERR-NOTFOUND` | 無い受注 → NOTFOUND。出荷済 → ERR-BIZ「出荷済の受注は編集できません。」。受注・明細の `RowVersion` を返す。明細は商品名の昇順 |
| B層 | 選択肢 | `EV-ORD-301` 手順 1・3-5、`OD-T3`、「選択肢の構築」 | 商品の選択肢に廃番が出ない。編集で既存の明細の廃番商品は、その行だけ選べる形で残る |
| B層 | 登録 | `EV-ORD-308` 手順 3、`ORD-T1` | 受注と明細が入る。`ShippedDate` は NULL。採番された受注 ID が返る |
| B層 | 編集の明細の行ごとの適用 | `EV-ORD-308` 手順 4-3、`OD-T6` | 削除の印の行だけ消える・変えた行だけ更新（明細の `RowVersion` + 1）・新しい行は挿入（`RowVersion` 1）・商品を変えた行は消して入れる。**全削除・再登録でない**（変えていない行の `RowVersion` が変わらない） |
| B層 | 楽観排他 | `EV-ORD-308` 手順 4-1・4-2、`HLD/Common.md` 9.1 節 | 保存で `Orders.RowVersion` + 1。読み込みの後に他で更新 → CONFLICT、消された → NOTFOUND（区別）。どちらも明細は変わらない（ロールバック） |
| B層 | 検証（まとめて） | `EV-ORD-308` 検証内容・手順 1 | 1 件でも違反なら更新しない。違反が複数なら全部返る。必須（顧客・担当者・受注日、明細の各列）、日付と `受注日 <= 要求納期`、数値の範囲（送料・単価 >= 0、割引 0〜1、数量 >= 1 の整数）、桁数（出荷先の 6 項目）、マスタの存在、明細の重複、明細 0 行、廃番（編集で読み込み時からある行は対象外） |
| B層 | 金額 | 「金額の再計算」、`HLD/Common.md` 3 節、`OD-T4` | 10 進数で計算（`Discount` は real）。明細金額の小数第 3 位の四捨五入 |
| B層 | 顧客・商品の取得 | `EV-ORD-302` 手順 2・3、`EV-ORD-306` 手順 3・4、`OD-T2` | 顧客の電話・住所、商品の単価・在庫。無い → NOTFOUND |
| E2E | 登録の初期表示 | `EV-ORD-301` 手順 2 | 受注 ID「（登録時に採番）」、受注日は当日、送料 0、明細は空行 1 行（割引 0・数量 1）、行削除は非活性 |
| E2E | 編集への遷移 | `EV-ORD-202`、`SC-ORD-02-B01` | 詳細の「編集」で、その受注の編集モード。出荷済は詳細に戻り ERR-BIZ（画面表示の後に出荷された場合を含む） |
| E2E | 顧客の変更 | `EV-ORD-302`、`ORD-T6` | 登録で出荷先に既定値。手入力があれば確認し、取り消すと上書きしない。編集では出荷先が変わらない。顧客を空にすると電話・住所が空、出荷先は変わらない |
| E2E | 明細の行 | `EV-ORD-304`・`305`、`ORD-T5` | 追加で既存行の値が残る、2 行以上で行削除が活性、1 行に戻ると非活性。削除で小計・合計が変わる |
| E2E | 商品の選択 | `EV-ORD-306`、`OD-T1`・`OD-T2` | 単価・在庫が入る。同じ商品を選ぶと元に戻り「この商品は既に明細に存在します。数量を変更してください。」。数量が在庫を超えると「在庫数を超えています。」の警告（保存は妨げない） |
| E2E | 再計算と入力の誤り | `EV-ORD-303`・`307` | 送料・単価・割引率・数量の変更で、価格・明細金額・小計・合計が変わる。誤った入力は項目にエラー、再計算しない |
| E2E | 保存 | `EV-ORD-308` 手順 1・6 | 違反があれば全部のエラーを出し、入力値を保ったまま留まる。成功で「受注 ID nnn を保存しました。」と、その受注の詳細へ |
| E2E | 保存の競合 | `ERR-CONFLICT`、`ERR-NOTFOUND` | 編集の表示の後に他で更新・削除された受注の保存 |
| E2E | キャンセル | `EV-ORD-309`、F-3 | 変更が無ければ確認なし。変更があれば「入力内容は保存されません。よろしいですか？」、取り消すと留まる。編集 → 詳細へ、登録 → 保持した一覧状態で一覧へ。DB は変わらない |
| E2E | メインボタン | 規約「画面共通」、1 回目の決定 4 | 保存はフッタのメインボタン。キャンセル・明細行追加・行削除はフッタの外 |
| 共通 | テストのデータ | 範囲の「データを書き換えるテスト」 | 既存の受注・顧客・商品を書き換えない。登録の受注は採番された ID で後片付け |
| 共通 | 1 回目の約束 | 範囲の「1 回目から引き継ぐこと」 | `/OrdTf/Edit?mode=new` を変えない（1 回目の E2E の期待を変えない） |
